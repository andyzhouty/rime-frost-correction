# 验证方法与边界

本仓库不公开本机原始探索日志、逐轮性能记录、私人测试词语或私有词库。设计结论维护在 EVOLUTION_AND_ARCHITECTURE.md。

安装器测试使用临时目录和通用示例，验证菜单添加、重复安装、备份、回退和上游校验。它们不会修改实际输入法。

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

性能研究应固定输入集合、词库、模型和候选命中定义。延迟单进程、固定两版本交错测量，至少独立复测；不要用减少调用次数直接推导加速，也不要把插桩成本分布当作真实改善。

后续平台验证需分别检查 Lua 与 Octagram 加载、字典编译、正确输入与纠错候选、原始预编辑、学习与重新部署。桌面安装脚本支持对应目录布局；这不等于所有前端版本已实机验证。Android 需另行验证应用的导入权限和插件版本。

发布时的实际验证结果与限制记录于下方；不包含逐轮原始记录。

## 0.1.0 发布检查

- 七项测试通过，覆盖菜单保留与幂等、异常配置、备份回退、学习数据保留、后续修改保护、离线校验、共享模型保护及 Lua 依赖完整性。
- Windows 隔离用户目录使用正常 Rime DLL 完成通用词库和三个方案的编译。
- 九组通用输入冒烟检查通过，包括正确拼音、邻键及交换输入；产生候选，纠错标记无重复，未发现 Lua 加载或运行错误。
- macOS、Linux、Android 尚未进行实机输入法验证。自动化测试用于验证安装逻辑，不代替各前端实机验收。
- 未执行公开版完整准确率或延迟基准，未把私人定制环境的成绩当作本版成绩。
