# 测试情况与验证方法

这篇文档帮助你了解哪些功能已经检查过，也给希望参与改进的用户提供测试方法。

## 当前测试情况

| 检查内容 | 结果 |
| --- | --- |
| 安装与回退逻辑、Lua 文件依赖 | 七项自动测试通过 |
| Windows、macOS、Linux 的安装器自动测试 | GitHub Actions 通过 |
| Windows 隔离环境的词库与方案编译 | 通过 |
| 九组普通拼音与纠错输入的基本检查 | 通过，候选正常产生，纠错标记无重复，实际输入保留 |
| macOS、Linux、Android 的实际输入法体验 | 待实机验证 |
| 当前发布方案的大规模准确率与延迟测试 | 待补充 |

“隔离环境”是独立的临时用户目录。“基本检查”用于确认方案能正常工作；更长时间的真实使用还可以帮助发现兼容性与体验问题。

## 安装后可以自己检查什么

1. 输入 `nihao`，确认能选到“你好”。
2. 输入 `jintain`，查看是否出现带 `≈` 的纠错候选，输入栏是否仍保留实际敲下的字母。
3. 尝试翻页、选择候选、提交文字和 Shift 切换。
4. 重新部署后，再确认输入正常。

如果出现问题，反馈时可以附上系统、输入法名称与版本、输入的拼音、期望候选和实际现象。部署失败时，相关报错也有助于定位原因。

## 运行自动测试（开发者）

在项目文件夹执行：

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

macOS 或 Linux 可能需要将 `python` 换成 `python3`。运行过安装脚本后，也可以使用 `.venv` 中的 Python。

测试使用临时目录，覆盖菜单保留、重复添加、文件校验、备份回退、修改保护和 Lua 模块依赖。

## 怎样比较速度

比较两个版本时，保持输入集合、词库、模型和电脑负载尽量一致。延迟测试一次只运行一个进程，让两个版本交替测试，再进行独立复测。

| 指标 | 怎样理解 |
| --- | --- |
| 平均延迟 | 所有按键耗时的平均值 |
| P50 | 一半按键的耗时不超过这个数值，反映通常情况 |
| P95 | 95% 按键的耗时不超过这个数值，帮助观察较慢情况 |
| P99 | 99% 按键的耗时不超过这个数值，更关注偶发卡顿 |
| Max | 本轮最慢的一次，容易受偶发调度和系统负载影响 |

速度之外，还要核对候选文本、顺序、注释和输入栏显示，检查长时间使用后的内存变化。分析耗时的测量代码可能带来额外开销，最终速度比较应在移除这些测量代码后进行。
